# Southern Passage — research history

An Antarctic voyage-planning research prototype for SIH26059. It illustrates how sea-ice observations and outlooks, iceberg drift, and route trade-offs might be brought into one review workspace. It is not ministry-certified software or navigation advice.

For independent private-host operation, health checks, verified review-ledger backups, and a future ministry gateway handoff, see [STANDALONE_OPERATIONS.md](STANDALONE_OPERATIONS.md).

## Current state

The operator-facing observed-route review now has a fail-closed evidence summary, 5-km ice-edge sensitivity check, optional caller-entered research vessel limits, and paired JSON/GeoJSON exports with one shared packet ID and digest. Observed path comparison also re-scores its **fixed** alternatives under hypothetical ±5-point ice changes using one common objective; it does not re-route or forecast them. The system **always withholds navigation clearance**: an entered limit is not a verified Polar Water Operational Manual, sensitivity is not a forecast interval, and an archived scene is not live voyage monitoring. The compact controls are in the Observations workspace; case sign-offs remain a separate gateway-gated review function. See [MINISTRY_INTEGRATION.md](MINISTRY_INTEGRATION.md).

An as-issued forecast archive has now begun separately from the portal: original Copernicus Marine GLO12 2026-10-02 bulletin files at 1/3/5/7 days are checksummed with native forecast/valid dates and local capture times. `ml/fetch_glo12_forecast.py` acquires the next bulletin and `ml/archive_glo12_forecast.py` validates each file. This first run has no measured future outcomes or calibrated uncertainty and is **not** connected to route clearance. See [the dataset guide](DATASETS_AND_MODELS.md#prospective-glo12-forecast-run-archive-begun-2026-10-02).

An authenticated Copernicus Marine acquisition has added June-August 2024 Antarctic Peninsula sea-ice, GLORYS near-surface current, and reprocessed L4 sea-surface wind subsets. `ml/evaluate_copernicus_fusion.py` now aligns these different geographic grids on the ice grid and runs a frozen August holdout against persistence. The new wind/current model **did not beat persistence** (3.721 vs 3.665 percentage-point RMSE on 53,816 matched August cells), so it remains research-only and is not selected for the app. The sparse ASCAT-only wind subset was also inspected but is unsuitable as a complete gridded forcing field. Historical publication times are unverified, and currents/wind are retrospective products. See [the report](outputs/copernicus-fusion-2024-aug-holdout.json) and [DATASETS_AND_MODELS.md](DATASETS_AND_MODELS.md).

The initial one-day SIC model is now explicitly selected and pinned in [config/initial-model.json](config/initial-model.json). It is the existing `sic-lag-regression-v1` trained from checksum-verified G02202 data, not a new operational model. The expanded 1989–2023 challenger remains unselected: on the common 2025 comparison its area-weighted RMSE improvement was only 0.037% and ice-edge disagreement was slightly worse. The API checks the selected model bytes, embedded fingerprint, frozen 2017–2024 holdout, and candidate decision before loading; an altered or swapped artifact makes readiness fail. Verify the release locally with `work\convlstm-env\Scripts\python.exe -m ml.verify_initial_model` and inspect `/api/v1/model/selection`. The selected model is research-only and forecasts SIC at one day; the multi-day voyage display is illustrative, not generated by this model. See [DATASETS_AND_MODELS.md](DATASETS_AND_MODELS.md) for the remaining scientific gates.

The observed-route comparison now includes a **research-only travel-time sensitivity**, separate from any vessel ETA. Its editable defaults are 10 kn in open water and 3 kn in ice-affected water. For each observed grid edge it linearly interpolates speed from midpoint SIC, sums nautical miles divided by assumed knots, and displays the times at 80% and 120% of both assumed speeds. This is an assumption sweep, not a calibrated uncertainty interval or published ship-performance law. Paths touching a cell with at least 70% observed SIC receive no time calculation; 70% is a conservative display-abstention rule, not a navigability threshold. The API reports no fuel estimate without a documented vessel-specific burn curve. No ship certificate, Polar Water Operational Manual, ice thickness/type, currents, weather, bathymetry, or iceberg-clearance assessment is implied.

The frozen Antarctic Peninsula research transects now have a separate three-platform VIIRS evaluation. Checksummed NOAA-21 and NOAA-20 June–August 2024 subsets complement the existing S-NPP subset; `ml/evaluate_independent_corridors.py` scores each platform separately against persistence and counts missing calendar days in the coverage denominator. Its frozen [report](outputs/viirs-2024-multiplatform-frozen-corridors.json) and `/api/v1/evaluations/multiplatform-corridors` endpoint report `insufficient_evidence`: the best platform supplies only 15–17% calendar point-day coverage on the three transects. Slightly lower RMSE on observed points is not route skill or safety evidence. These same transects have been inspected before, so this is not a pristine prospective test.

This command reproduces the current fit/holdout split over the archived paper test period (fit through 2020-08-06; validate 2020-08-07-2022-12-31). For actual training, substitute quality-controlled multi-decadal files from the data catalogue. The trainer reports MAE/RMSE alongside persistence RMSE and requires at least 100 readable daily grids. Inspect variable, scaling, masks, missing dates, product transitions and grid alignment; use multiple untouched years and rolling-origin/seasonal/regional metrics before model selection. For an independent product/period test without refitting, use `ml/evaluate_sic.py <independent-netcdf-dir> --model models/sic_baseline.json --output outputs/external-evaluation.json`. Trainer validation scope is derived from the dataset manifest; model artifacts and evaluation reports include coefficient fingerprints.

For a multi-window test on the G02202 archive (or another daily Antarctic SIC archive), run `ml/rolling_evaluate_sic.py <archive-dir> --train-years 8 --validation-years 2 --step-years 2 --output outputs/rolling.json`. This fits expanding chronological windows and scores each later two-year block against persistence, streaming the source archive once. All inputs carry cell-equal pooled and calendar-month metrics; G02202 additionally gets ground-area-weighted totals by month, broad latitude band and fold, with weights derived from the product CRS and projection scale. The cell-equal and area-weighted statistics are complementary diagnostics, not route-scale validation. Other datasets must not be labeled area-weighted unless an appropriate geospatial cell-area method is added.

For a small Antarctic ice-motion acquisition that can later support an advection-baseline experiment, install the optional NASA Earthdata client, first inventory the authenticated NSIDC HTTPS archive, then download only a reviewed time window. The old NSIDC-0116 collection metadata remains in CMR, but its granule search currently returns no granules for this product; the fetcher therefore uses the product's documented HTTPS directory structure instead of treating a zero-result CMR query as proof that files are unavailable:

```powershell
work\convlstm-env\Scripts\python.exe ml\fetch_nsidc0116.py work\datasets\nsidc0116-south-2024-jun-aug --start 2024-06-01 --end 2024-08-31 --list-only
work\convlstm-env\Scripts\python.exe ml\fetch_nsidc0116.py work\datasets\nsidc0116-south-2024-jun-aug --start 2024-06-01 --end 2024-08-31
```

Downloading requires a NASA Earthdata Login. The default reads a locally configured `_netrc` (Windows) or `.netrc` following [NSIDC's official access guide](https://nsidc.org/data/user-resources/help-center/programmatic-access-guide-data-daacdataapps); add `--interactive-auth` to prompt for credentials for one run without saving them. Never put credentials in the repository, command history, or a manifest. Both inventory and downloading authenticate before accessing the directory. The manifest's `complete` flag means every matching archive file was downloaded and structurally checked, not that all dates/cells contain valid vectors. `ml/align_nsidc0116_archive.py` builds a date-complete, checksummed alignment archive from the acquired NSIDC manifest and a G02202 reference. For the sample acquisition above:

```powershell
work\motion-research-env\Scripts\python.exe ml\align_nsidc0116_archive.py work\datasets\nsidc0116-south-2024-jun-aug work\datasets\g02202-v6-post2016\sic_pss25_20240101-20241231_v06r00.nc work\datasets\nsidc0116-aligned-2024-jun-aug --start 2024-06-01 --end 2024-08-30
work\motion-research-env\Scripts\python.exe ml\evaluate_nsidc0116_advection.py --motion-dir work\datasets\nsidc0116-south-2024-jun-aug --aligned-dir work\datasets\nsidc0116-aligned-2024-jun-aug --sic-file work\datasets\g02202-v6-post2016\sic_pss25_20240101-20241231_v06r00.nc --start 2024-06-02 --end 2024-08-31 --fit-through 2024-07-16 --output outputs\nsidc0116-advection-2024-jun-aug.json
```

The evaluator verifies both manifests and each source/aligned file hash, exact SIC grid coordinates, QA masks, and common-valid coverage. It chooses a convex blend coefficient only on the earlier fit dates and scores the later dates against persistence. The June–August 2024 run selected lambda 0.8 on 45 fit dates and reduced pooled MAE by 3.665% and RMSE by 5.075% on 46 later dates (`outputs/nsidc0116-advection-2024-jun-aug.json`). A stronger cross-year test selected lambda 0.7 using **2023 only**, then froze it for all evaluable 2024 dates through `--lambda-report`: MAE fell from 0.032062 to 0.031058 (3.132%) and RMSE from 0.057468 to 0.054879 (4.505%) across 354 dates and 5,417,459 correlated common-valid cell-days. Ten zero-coverage dates were excluded. The reproducible, provenance-linked report is `outputs/nsidc0116-advection-2024-2023fit-linked.json`; full procedure and caveats are in [DATASETS_AND_MODELS.md](DATASETS_AND_MODELS.md). The D-1 motion date is an explicit retrospective assumption: the NSIDC daily date label does not establish publication or availability time. This same-product diagnostic is not independent validation, is not area- or route-weighted, has no calibrated uncertainty, and does not assess route passability or safety. No motion-informed model is currently promoted or connected to the service.

If Earthdata is not configured, EUMETSAT's open OSI-455 daily Antarctic sea-ice drift CDR provides a lower-resolution retrospective alternative (1991-2020, 75 km, 24-hour displacement). The 2017–2020 acquisition and frozen-year comparison are documented in [DATASETS_AND_MODELS.md](DATASETS_AND_MODELS.md). The fitted blend reduced pooled MAE by only 0.343%, and strict-quality motion covered just 183 days per year, mostly April–September. G02202's daily date coordinate does not establish the field's real-time availability, so this comparison does not prove operational causality or useful generalized forecast skill. Motion is not integrated into the API/model, and sea-ice motion is not iceberg motion.

## Run the API

With dependencies installed:

```powershell
uvicorn service.main:app --host 127.0.0.1 --port 8000
```

For the VIIRS observation catalog and map layer, point the API at the acquired dataset directory:

```powershell
$env:SOUTHERN_PASSAGE_VIIRS_DATA = "work\datasets\polarwatch-viirs"
uvicorn service.main:app --host 127.0.0.1 --port 8000
```

Local development uses `http://127.0.0.1:8000` by default; on `localhost` only, `?api=http://127.0.0.1:8000` can override it. On non-local hosts the browser defaults to its own origin, so the recommended deployment is to publish the app and proxy `/api/*` through the same ministry TLS/OIDC gateway. The gateway should authenticate the user's OIDC session, authorize the requested action, and inject the API's service bearer credential on its server-side upstream request. Do not put `SOUTHERN_PASSAGE_API_TOKEN` in JavaScript, HTML, a public configuration endpoint, or browser storage. For a separate approved API origin, inject its base URL through `window.SOUTHERN_PASSAGE_API_URL`, configure that exact HTTPS CORS origin, and have the identity gateway enforce the user's session on the cross-origin credentialed request before adding the server-side bearer token. The API permits unauthenticated CORS preflight only so the browser can make the subsequent request; the actual `/api/*` request still requires the service credential. The observation endpoint is read-only and returns only the selected regional SIC grid and provenance.

`GET /healthz` is liveness; `GET /readyz` indicates whether a model artifact is present; `GET /api/v1/model` returns model provenance, its strict same-product 2017-2024 holdout, the 2025 sensor-era check, independent-product diagnostics, and a separate ten-fold 1997-2016 rolling-origin benchmark. The latest frozen S-NPP and NOAA-21 transfer checks cover 19 target days (2026-09-03 through 2026-09-21) in one 100-km region; their correlated cell-time counts are not independent trials or route-scale validation. The NOAA sample was about nine days behind on 2026-09-30 and is marked stale by demo recency thresholds. The rolling benchmark fits a different earlier-only model per fold and is explicitly not a score for the currently packaged coefficients. `POST /api/v1/forecast/sic` accepts two same-shaped 2-D SIC fraction grids (`0`-`1`), a required validity mask, CRS, affine transform, and source/date metadata. `GET /api/v1/observations/sic/{date}/forecast` derives the same one-day forecast from two consecutive, locally mounted scenes of the same VIIRS product/platform and grid, whose file hashes have been verified against their manifest. It refuses less than 10% common valid pixels; this display gate is a demo placeholder and does not imply uniform spatial coverage. Masked cells return `null`. Forecast responses include a UUID run ID, coefficient fingerprint, full-artifact SHA-256, valid-cell count, grid metadata, `decision_status: research_only`, and the packaged model's same-product holdout plus its limited regional VIIRS transfer check. The generic POST endpoint explicitly notes that its caller-supplied inputs are unverified; both responses state that no calibrated uncertainty or safety assessment is produced. API docs are available at `/docs` for local development only.

`GET /api/v1/icebergs/observed-tracks?as_of_date=YYYY-MM-DD&window_days=30` returns GeoJSON track snippets assembled from non-interpolated BYU/NIC sensor positions, with same-day sensor locations averaged, position ages, archive SHA-256, and an explicit historical-only warning. The route refuses dates after the BYU v8.0 landing page's published coverage end (2025-04-22), because this local archive contains later records that have not been confirmed by the source. Configure `SOUTHERN_PASSAGE_ICEBERG_TRACKS` to the archive ZIP; its sibling `manifest.json` must identify the complete v8.0 dataset and matching SHA-256. Docker Compose mounts the local archive directory read-only. These tracks are for retrospective context only, not live iceberg locations, a complete census, drift predictions, or route-safety assessment.

`POST /api/v1/route/exposure` accepts a WGS84 GeoJSON `LineString`, an available observation date, and an optional `analysis_half_width_km` (0–20 km per side; default 5 km). It returns centerline statistics plus a geodesic context swath summary, coverage, source-file provenance, map-overlay coordinates, and 5-km profiles of mean/max concentration. Set the width to zero for centerline-only analysis. The swath is a fixed-width data-analysis context, not a vessel-specific corridor or safety clearance; it does not forecast future ice, account for ship capability or other hazards, or determine whether a route is passable or safe.

Forecast inputs are schema-bounded to at most 500×500 cells and are checked for rectangular shape, finite SIC fractions, boolean validity masks, recognized CRS, and a non-singular affine grid transform. API write bodies also have a hard 16 MiB cap enforced for declared and chunked uploads before parsing. `APP_ENV=production` fails closed at startup unless `SOUTHERN_PASSAGE_API_TOKEN` has at least 32 characters and `CORS_ORIGINS` is an explicit non-local allowlist. With a token configured, all `/api/v1/*` routes require `Authorization: Bearer …`; local health endpoints remain available to the orchestrator. This shared service credential is only an interim service-to-service boundary, not ministry user authentication or authorization. A ministry gateway must validate OIDC identities and roles, inject service identity, enforce rate limits (and tighter endpoint-specific size limits), and preserve actor-level audit records; it should also restrict direct network access to this container. Never expose the container directly to the public internet.

The container build is pinned to a Python base-image digest and hash-locked Python dependencies; raw datasets and local virtual environments are excluded from its build context. The image runs as non-root and includes a readiness health probe. It still requires ministry CVE/license review, image signing, an approved registry/hosting boundary, and ministry identity controls before deployment. Bindings default to loopback. For a production-mode smoke test, configure `APP_ENV=production`, a high-entropy service token, and exact browser origins in the deployment secret/config store. This deliberately rejects the checked-in local CORS defaults when production mode is selected.

## Ministry integration boundary

The research data pipeline now includes a staged, checksummed NOAA VIIRS refresh gate (`ml/refresh_viirs.py`) and a frozen-corridor one-day backtest (`ml/evaluate_route_corridors.py`). The active-feed status is `/api/v1/observations/active/status`; the backtest is `/api/v1/evaluations/frozen-corridors`. Current 2024 corridor coverage is too sparse for a positive quality gate, and no live refresh was promoted. See [MINISTRY_INTEGRATION.md](MINISTRY_INTEGRATION.md) for the scheduler, policy, and acceptance boundaries.

The deployment responsibilities, audit correlation contract, identity boundary, and pre-pilot acceptance gates are detailed in [MINISTRY_INTEGRATION.md](MINISTRY_INTEGRATION.md). The API now returns an `X-Request-ID` and emits body-free structured `/api/*` access events; actor identity and immutable retention remain the gateway's responsibility.

Before an external pilot, the ministry/host agency must select its identity provider and hosting boundary, approve data/licensing and retention, specify ships/voyage hazards and safety policies, and nominate scientific and maritime-safety owners. Put the API behind the ministry's approved TLS ingress, authentication/authorization, rate limiting, audit logging, secret management, monitoring, backup and incident response. Add provenance per output, freshness/quality status, calibrated uncertainty, model/data version, reproducible run ID, explainability, human sign-off, fail-closed behavior and interoperable geospatial interfaces (e.g. OGC API Features/Maps or ministry-approved equivalents). Do not use this prototype to make or automate navigation decisions.
